# სკოლის ექსპორტი, offboarding, შენახვა და წაშლა

განახლებულია: 2026-10-03. ეს დოკუმენტი მოითხოვება `CLAUDE-PLATFORM-MODULES.md` §14-ით. აქ აღწერილია **პროცესი**. ავტომატური წაშლის ან მასობრივი ექსპორტის endpoint კოდში **განზრახ არ არის**, სანამ შენახვის სამართლებრივი ვადები და დამტკიცების წესი არ დადასტურდება.

## პრინციპები

- **მოდულის გამორთვა წაშლა არ არის.** `feature:<name>` მხოლოდ route-ებს ხურავს, მონაცემი კი ინახება. ამას `PlatformAdministrationTest` ამოწმებს.
- **სკოლის მონაცემის ფლობელი სკოლაა.** ექსპორტსა და წაშლას ითხოვს სკოლის უფლებამოსილი პირი: დირექტორი ან სკოლის კანონიერი წარმომადგენელი. პლატფორმის ოპერატორი ამას თავისი ინიციატივით არ აკეთებს.
- **ყოველი ნაბიჯი აღირიცხება** `platform_audit_events`-სა და სკოლის `audit_events`-ში.
- **პირადი/ჯანმრთელობის/ფინანსური მონაცემი ექსპორტში შედის მხოლოდ მიზნისთვის საჭირო მოცულობით** (`docs/02` §199).

## Offboarding-ის ნაბიჯები (ხელით, ორი ადამიანის დასტურით)

1. **მოთხოვნა.** სკოლა წერილობით ითხოვს offboarding-ს და მიუთითებს მიზეზს და სასურველ თარიღს. ოპერატორი მოთხოვნას `platform_audit_events`-ში ინიშნავს.
2. **დასტური.** მოთხოვნას ამოწმებს სკოლის მეორე უფლებამოსილი პირი და პლატფორმის მეორე ოპერატორი (ოთხი თვალის პრინციპი).
3. **ექსპორტი.** სკოლას გადაეცემა მისი მონაცემები, ფორმატი შეთანხმდება სკოლასთან. ამჟამად ეს ხდება ოპერატორის სკრიპტით staging-ის გავლით და არა web endpoint-ით. ფაილი იშიფრება, გადაეცემა ვადიანი ბმულით და აღირიცხება.
4. **გაყინვა.** `tenants.is_active = false`. ყველა დომენი 404-ს აბრუნებს, მონაცემი ჯერ ინახება.
5. **შენახვის ვადა.** მონაცემი ინახება იურიდიულად დადასტურებული ვადის განმავლობაში. ამჟამად ვადა **არ არის განსაზღვრული** (`config/health.php` → `retention_years = null`, ფინანსებს ბუღალტრული აღრიცხვის ვადა სჭირდება).
6. **წაშლა.** ვადის ამოწურვის შემდეგ ხორციელდება ცალკე, დოკუმენტირებული migration/command-ით. ამას წინ უსწრებს backup, dry-run ანგარიში და ორი ადამიანის დასტური. backup-ების შენახვის ვადაც ამ წესს ექვემდებარება.

## რა არის ღია (სკოლის/იურისტის გადაწყვეტილება)

- მოსწავლის, ჯანმრთელობის და ფინანსური ჩანაწერების შენახვის კანონიერი ვადები.
- ექსპორტის ფორმატი: OneRoster CSV, JSON ან სხვა.
- ვის აქვს უფლება, მოითხოვოს წაშლა სკოლის სახელით.
- `APP_KEY`-ის როტაციის გეგმა. დაშიფრული ჯანმრთელობის ველებისთვის საჭიროა `APP_PREVIOUS_KEYS`. როტაცია ძველი გასაღების შენახვის გარეშე მონაცემს წაუკითხავს ხდის.
