  - „არქივი / განსახილველი“ საიტზე **არასდროს** ჩანს.
  - ძველი WordPress-ის category/tag ID-ები იმპორტის ჩანაწერებში უცვლელად რჩება.
- **`content:place-categories`:** ნაგულისხმევად preview-ა, `--commit`-ით ინახება, `--report=` per-record ანგარიშს წერს.
  - ის მხოლოდ განთავსებას წერს. **ტექსტს, თარიღს, სტატუსს, slug-სა და მედიას არ ეხება**, არაფერს აქვეყნებს და არაფერს აუქმებს.
  - CMS-ში ხელით გაკეთებული განთავსება დაცულია და `conflict`-ად ინიშნება.
  - გამოქვეყნებული ჩანაწერი, რომელიც არქივისთვისაა შემოთავაზებული, `conflict`-ია და არ უქმდება.
  - ხელახალი გაშვება `unchanged`-ს იძლევა.
- **`content:sync-body-media`:** ნაგულისხმევად preview-ა, `--commit`-ით ინახება. მან უნდა გადმოიტანოს ის, რაც plain-text იმპორტმა დაკარგა: inline სურათები, გალერეები (რიგი, alt, caption) და დანართები (PDF/Word/Excel, ლეიბლით, MIME-ით, ზომით, sha256-ით).
  - წყარო raw API HTML-ია. სურათად აიღება **ორიგინალი** WordPress-ის media ID-ით; ვარიანტი მხოლოდ მაშინ, თუ ორიგინალი არ შეგროვებულა, და `variant_only` ნიშნით.
  - ფაილი უნდა ემთხვეოდეს manifest-ის checksum-ს და როლის MIME ტიპს: HTML error page `.jpg`-ად უარყოფილია.
  - emoji და ცარიელი `<img/>` ანგარიშში ჩანს, მაგრამ არ ებმის.
  - არსებულ განსხვავებულ ნაკრებს `conflict` ეწერება და არ გადაიწერება.
- **საჯარო rendering:**
  - hub-გვერდზე „{კატეგორია}: მასალები“, მხოლოდ გამოქვეყნებული ელემენტები, თავდაპირველი თარიღით.
  - დეტალურ გვერდზე breadcrumb hub-ისკენ, გალერეა/სურათები და „დოკუმენტები“.
  - `/news`-იდან ამოდის დოკუმენტების კატეგორიის პოსტები. მათი URL `/news/…` უცვლელია, ისინი `/official-documents`-ზე ჩანს და არ დუბლირდება.
  - ყველაფერი initial HTML-შიც არის (`partials/public-content`).
- **CMS:** გვერდის/პოსტის რედაქტორში „საიტის განყოფილება“ (კატეგორია + ქვეგანყოფილება), audit `content.placement_changed`-ით.
