# არსებული aisi.edu.ge-ის კონტენტის გადატანა და სარედაქციო დამუშავება

## 1. მიზანი და ფარგლები

მომხმარებლის დავალებით სკოლის საჯარო ვებგვერდიდან იქმნება ლოკალური გადასატანი პაკეტი: გვერდები, სიახლეები, საჯარო პედაგოგთა პროფილები, დოკუმენტების გვერდები, მედია და დაკავშირებული რესურსების ინვენტარი. ორიგინალები ინახება ახალი ტექსტებისგან დამოუკიდებლად.

ეს არ არის WordPress მონაცემთა ბაზის/ადმინისტრატორის სრული backup. არ მოპოვებულა ავტორიზებული EduPage მონაცემები, draft/private WordPress მასალა, სკოლის ელფოსტა, ფორმის მიღებული განაცხადები, plugin-ის კონფიგურაცია და სერვერის ფაილთა სისტემა. ეს გამიჯვნა უნდა დარჩეს შემდგომი მიგრაციის ანგარიშშიც.

გამოყენებული საჯარო წყაროებია `https://aisi.edu.ge/`, `/wp-json/wp/v2/pages`, `/posts`, `/media`, `/wp-sitemap.xml` და მისგან/გვერდების ბმულებიდან ნაპოვნი same-site მისამართები. ავტორიზაცია არ გამოყენებულა; სკოლაში არაფერი დაწერილა და production ბაზა არ შეცვლილა.

## 2. გადასაცემი ფაილები

`content-migration/` შეიცავს:

| ფაილი / საქაღალდე | დანიშნულება |
|---|---|
| `raw/api/` | საჯარო API-ის მიღებული JSON გვერდები ორიგინალური HTML ველებით |
| `raw/pages/` | საჯარო HTML გვერდების ლოკალური ასლები, URL-ის hash-ით |
| `raw/sitemaps/` | sitemap ინდექსი და მისი შვილობილი რუკები |
| `sitemap-inventory.json` | sitemap/API-დან აღმოჩენილი მისამართები |
| `rendered-pages.json` | გვერდი → raw ფაილი → ტექსტი/ბმულები/სურათები; extraction არ არის დადასტურებული სარედაქციო ვერსია |
| `content-records.json` | ძირითადი გვერდებისა და სიახლეების პირველადი გასუფთავებული extraction |
| `assets/` | იმავე საიტის საჯაროდ დაკავშირებული ფაილების ლოკალური ასლები |
| `asset-manifest.json` | source URL → local path → ზომა/checksum/status; უფლებები დასადასტურებელია |
| `external-links.json` | სხვა საიტების რესურსების ბმულები; გარე წიგნები არ ჩამოტვირთულა |
| `cms-import.json` | გადასამუშავებელი, ყველა draft სტატუსის მქონე კონტენტის ჩანაწერები |
| `clean/*.md` | თითო ჩანაწერზე ახალი/გასუფთავებული ტექსტი, ორიგინალი და გადასამოწმებელი საკითხები |
| `redirect-map.csv` | ძველი მისამართიდან ახალი მისამართის წინადადება, არა უკვე ჩართული 301-ები |
| `failures.json` | მიუწვდომელი გვერდების/ფაილების ზუსტი ანგარიში |
| `collection-report.json` | შეგროვების რეალური რაოდენობები, დრო და ფარგლები |

თუ ანგარიში/manifest ჯერ არ არსებობს, შეგროვების პროცესი დასრულებული არ არის. საბოლოო რაოდენობებისთვის გამოიყენეთ ანგარიშის ფაილი და არა ძველი commentary ან API-ის მხოლოდ პირველი header. API-ს pagination header-ის total შეიძლება დაბრუნებული საჯარო ჩანაწერების რაოდენობას არ ემთხვეოდეს; ასეთი სხვაობა ცალკე უნდა დაფიქსირდეს და არ ჩაითვალოს უხილავი მონაცემის წარმატებულ ექსპორტად.

სკრიპტები: `scripts/collect-public-content.py` აგროვებს საჯარო მასალას; `scripts/prepare-school-content.py` ქმნის CMS-ის ჩანაწერებს და დიზაინის საცნობარო კონტენტს. პირველი სკრიპტის ხელახალი გაშვება იგივე საქაღალდეში აგრძელებს HTML/asset cache-დან, თუმცა API snapshot-ებს თავიდან იღებს; ცალკე თარიღის backup-ისთვის არსებული პაკეტი ჯერ უცვლელად შეინახეთ სხვა დირექტორიაში. სკრიპტი შეიძლება დიდ ქსელურ სამუშაოს ასრულებდეს — მიზეზის გარეშე ხელახლა არ გაუშვათ.

## 3. რა გალამაზდა და რა დარჩა ორიგინალად

**სარედაქციოდ გადაწერილია** ძირითადი სკოლის ისტორია, მისია, „რატომ აისი“, დირექტორის მისალმება და კონტაქტის გვერდი. ტექსტები გამარტივებულია, სტრუქტურირებულია და ზედმეტი განმეორებები/დაუდასტურებელი გარანტიები ამოღებულია. ორიგინალის სრული გასუფთავებული ტექსტი იმავე ჩანაწერში რჩება. დირექტორის სახელით ახალი ტექსტი საბოლოოდ შესაბამისმა პირმა უნდა დაამტკიცოს.

**დანარჩენი მასალა** ძირითადად ტექნიკურადაა გასუფთავებული ძველი HTML/shortcode გაფორმებისგან. ეს არ ნიშნავს ყველა ისტორიული სიახლის ხელახლა დაწერას ან ყველა ფაქტის დამოუკიდებლად დადასტურებას. სიახლის თავდაპირველი გამოქვეყნების თარიღი შენარჩუნებულია. კატალოგებში ძველი sidebar/შაბლონის ტექსტის შემდგომი human review შეიძლება საჭირო გახდეს.

**ოფიციალური წესები/ფორმები/ფაილები** არ გადაწერილა სამართლებრივი აზრის შეცვლით. შიდა რეგულაციები, ჩარიცხვის საბუთები, ავტორიზაციის სტატუსი, ფინანსური პირობები, ვარშავის პარტნიორობის 20%-იანი პირობა და განცხადებაში დირექტორის სახელი სკოლამ ცალკე გადაამოწმოს.

**გარე წიგნები** ბმულებადაა აღწერილი. მათზე ბმული არ გვაძლევს ხელახალი გავრცელების უფლებას. same-site ასლის ლოკალური შენახვაც თავისთავად არ ნიშნავს სხვა სკოლებისთვის გასაყიდ პროდუქტში გამოყენების უფლებას.

## 5. დიზაინში ასახული შედეგი

ახალი `/school` გვერდი შეიცავს კატეგორიებს: სკოლის შესახებ, სკოლის ამბები, პედაგოგები და დოკუმენტები. არის ძიება, ტექსტის წაკითხვა, თავდაპირველი თარიღები, წყაროს ბმული და დაკავშირებული რესურსები. კონტენტი მოდის `design/app/school/content.json`-დან. პროტოტიპი მთლიანად noindex კონცეფციაა, არა production CMS.

მთავარ გვერდზე გადავიდა სკოლის ისტორიის მოკლე ტექსტი, რეალური წყაროს საკონტაქტო ინფორმაცია და ბოლო სიახლეები. მშობლის/მოსწავლის პორტალის მონაცემები ამ კონტენტით არ შეცვლილა: ისინი კვლავ გამოგონილი დემო ჩანაწერებია.

## 6. Claude Code — რეალურ CMS-ში იმპორტი

პირველ რიგში შეამოწმე უკვე არსებული Content models/controllers/importer. ინვენტარის დროს არსებობდა `App\Domain\Content\Models\Page`, `PageRevision` და `Post`; Page იყენებდა `slug`, `locale`, `title`, `excerpt`, `blocks`, `status`, `published_at`, `seo_title`, `seo_description`. კოდი პარალელურად ვითარდება; ბოლო მდგომარეობა ხელახლა წაიკითხე.

`cms-import.json` შუალედური კონტრაქტია, არა პირდაპირ Eloquent fill-ისთვის მზა payload. დაწერე idempotent importer ამ წესებით:

1. სავალდებულო tenant არგუმენტი და explicit trusted school context. შემთხვევით სხვა სკოლაზე იმპორტი არ უნდა მოხდეს.
2. default `--dry-run`; რეალური import მხოლოდ მითითებული ადგილობრივი/staging ბაზისთვის. არცერთი კონტენტი ავტომატურად published არ გახდეს.
3. წყაროს identity: `(tenant_id, source_system='aisi-wordpress', key)`. WordPress ID ერთ სკოლაზე/ტიპზეა უნიკალური; legacy URL-based key-ს source_id=null შეიძლება ჰქონდეს.
4. string body გადაიყვანე აპლიკაციის მხარდაჭერილ ტიპიზებულ paragraph/heading/link blocks-ად. დაუმუშავებელი WordPress HTML/shortcode/JavaScript არ შეიტანო CMS rendering-ში.
5. mapped `target_path` ახალი route-ის წინადადებაა; გადაამოწმე რეალური routing და slug წესები. merge_review rows არ ქმნის მეორე ერთნაირ გვერდს.
6. ყველა იმპორტს ჰქონდეს import batch, source URL/date/checksum და განხილვის სტატუსი. არ დაკარგო ორიგინალი სარედაქციო ცვლილების შემდეგ.
7. ხელახალი import არ ქმნის დუბლიკატებს და არ გადაწერს რედაქტორის ადგილობრივ ცვლილებას. თუ source და local ორივე შეიცვალა, შექმენი conflict review; საჭიროების შემთხვევაში ახალი revision.
8. უკვე არსებული გვერდის ჩანაცვლება შეასრულე revision-ით და შესაბამისი approval-ით; არ გაუშვა truncate/migrate:fresh.
9. assets გადაიტანე სწორი tenant storage-ზე, MIME/extension/checksum/ზომის გადამოწმებით და scan-ით. download_status=saved მარტო ვერ ადასტურებს სწორ PDF/სურათს. პროგრამის private/public classification და გავრცელების უფლება ცალკე შეამოწმე.
10. გარე წიგნები ინახება external resource links-ად; სხვა სკოლის tenant-ში აისის მედია არ გადაკოპირდეს.
