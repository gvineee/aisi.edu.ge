## EduPage (`https://aisi.edupage.org/`)

- **გადაწყვეტილება ჯერ არ არის მიღებული**: retain / official-integrate / phased-replace.
- კოდში არაფერია აშენებული, რაც ივარაუდებს API/SSO ხელმისაწვდომობას. საჯარო საიტზე EduPage-ის ბმულის მოცილება/შენარჩუნება ჯერ არ საჭიროებია გადაწყვეტილებას, რადგან ჩვენი ახალი საჯარო საიტი (ჯერჯერობით) არ შეიცავს პორტალში შესვლის ბმულს, რომელიც EduPage-ს ჩაანაცვლებდა — `login()` ბმული მიდის ჩვენს Fortify-ზე, არა EduPage-ზე.
- **სანამ გადაწყდება**: ნებისმიერი მომავალი "ჩემი აისი" ფუნქციონალი (განრიგი, ჟურნალი) აშენდება ჩვენს schema-ზე, სინთეზური seed მონაცემებით, დოკუმენტირებული import კონტრაქტით. რეალურ EduPage მონაცემებზე გადართვა დაბლოკილად დარჩება მანამ, სანამ ოფიციალური export/API დადასტურდება.

## ბიბლიოთეკის მიგრაცია (`https://aisi.edu.ge/online-library/`)

- ამჟამად `library_resources` ცხრილი შეიცავს მხოლოდ 3 სინთეზურ ჩანაწერს (ტესტ/დემო მონაცემი, `TenantSeeder`).
- რეალური კატალოგის მიგრაციისთვის საჭიროა: inventory (სათაური/ავტორი/კლასი/საგანი/არსებული URL), თითოეულის გავრცელების უფლების დადასტურება. ბმულის არსებობა ძველ საიტზე გავრცელების უფლებას არ ადასტურებს.

## გადახდის პროვაიდერი

- **არჩეული არ არის.** `PAYMENT_PROVIDER=sandbox` მხოლოდ `.env.example`-შია placeholder-ად; ფინანსური მოდული (invoices/payments/webhooks) ჯერ არ დაწყებულა.
- საჭირო გადაწყვეტილებები production-მდე: ბანკი/PSP, merchant წევრობა, webhook კონტრაქტი, hosted checkout-ის ინტეგრაციის დეტალები.

## ჰოსტინგი და SLA

- ლოკალური dev გარემო: Windows + Herd PHP + Windows service PostgreSQL + portable (non-service) Redis. **ეს არ არის production hosting გადაწყვეტილება** — production-ისთვის საჭიროა ცალკე ჰოსტინგის/SLA-ის არჩევანი (docs/02 §12).

## სხვა ღია საკითხები (docs/02 §14-დან, უცვლელი)
