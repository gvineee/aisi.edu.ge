კვლევის თარიღი: 2026-09-10. ეს არის განვითარების რეკომენდაცია და განხორციელების დანართი, არა ბაზრის სრული რეიტინგი. შეფასება ეყრდნობა პროვაიდერების ოფიციალურ აღწერებს; მათი მარკეტინგული ეფექტიანობის დაპირებები დამოუკიდებლად არ გაზომილა. ზოგი ფუნქციის ხელმისაწვდომობა დამოკიდებულია პროვაიდერის პაკეტზე/სკოლის კონფიგურაციაზე. აისში API ინტეგრაცია ამ კვლევით არ დასტურდება.

## 3. მშობლის მოქმედებების ცენტრი

ერთ სიაში: უპასუხო თანხმობა, საჭირო შეხვედრა, გადახდის ვადა, დაბრუნებული განაცხადი. ჩანაწერს აქვს ბავშვი, წყარო, სათაური, ვადა, სტატუსი და პირდაპირი მოქმედება. დასრულების ფაქტი მოდის შესაბამისი მოდულიდან, არა მხოლოდ შეტყობინების დახურვიდან.

მოდელი: `action_items(tenant_id, recipient_id, student_id, source_type, source_id, due_at, status, completed_at)`; უნიკალური source/recipient identity დუბლიკატების თავიდან ასაცილებლად. შეტყობინების წაკითხვა არ უდრის თანხმობას/გადახდას. გაუქმებული guardian link დაუყოვნებლივ აუქმებს წვდომას.

გაუქმებული ღონისძიების მოქმედება ავტომატურად დაიხუროს შესაბამისი სტატუსით. დროის ზონა და ვადის საზღვარი განისაზღვროს სკოლით. private დეტალები არ მოხვდეს lock-screen push-ის ტექსტში.

## 4. შეხვედრის დაჯავშნა

`conference_sessions`, `conference_slots`, `conference_bookings`: tenant, teacher, school period, start/end, capacity, family/student, status, cancellation, optional meeting location. პედაგოგი/ადმინისტრაცია აქვეყნებს დროებს; მშობელი ხედავს თავისი ბავშვისთვის დაშვებულ მასწავლებელს.

მდგომარეობები: available → held (თუ checkout/მრავალნაბიჯიანი ნაკადია) → confirmed → cancelled/completed. server transaction + უნიკალური slot booking/locking; UI-ის „დაკავებულია“ საკმარისი არაა. ოჯახის და მასწავლებლის დროის გადაფარვაც შეამოწმეთ. ერთზე მეტ ბავშვზე საერთო შეხვედრის პოლიტიკა სკოლის პარამეტრია.

თუ დრო უკვე დაიკავა სხვამ, მოთხოვნა დაბრუნდეს კონფლიქტის განმარტებითა და განახლებული თავისუფალი დროებით; არ შეიქმნას ორი ჯავშანი. reschedule იყოს atomic. გაუქმების/ცვლილების ვადა და reminder მართვადი იყოს. ვიდეოშეხვედრის ბმული მხოლოდ მონაწილეებისთვის.

## 5. გაცდენის მოთხოვნა

`absence_requests`: მოსწავლე, თარიღი/ინტერვალი, საჭირო მინიმალური მიზეზის კატეგორია, ავტორი guardian, სტატუსი, განმხილველი და გადაწყვეტილების დრო. მდგომარეობები: submitted → accepted/declined/withdrawn. პედაგოგი/სკოლის უფლებამოსილი თანამშრომელი განიხილავს.

მოთხოვნა არ არის ფაქტობრივი დასწრება და ავტომატური გამართლება. მიღებული მოთხოვნა ცალკე უკავშირდება შესაბამის attendance ჩანაწერს სკოლის წესით. ერთი interval-ის დუბლიკატი/უკან დაბრუნებული თარიღი/ღონისძიების არდადეგები დამუშავდეს. სამედიცინო დოკუმენტი default მოთხოვნა არ იყოს; საჭიროების შემთხვევაში restricted კატეგორია, retention და პასუხისმგებელი როლი ცალკე განისაზღვროს.

## 6. მშობლის თანხმობა

`consent_requests`, immutable `consent_request_versions`, `consent_responses`: ზუსტი ღონისძიება, პირობების ვერსია/hash, ბავშვი, უფლებამოსილი guardian, პასუხი, დრო, გაუქმება. პასუხები: pending/accepted/declined/withdrawn. „ვეთანხმები“ ღილაკამდე მშობელმა უნდა ხედავდეს კონკრეტულ პირობებს.

პროგრამის/ტრანსპორტის/ფასის არსებითი ცვლილება ქმნის ახალ ვერსიას და საჭიროების შემთხვევაში ახალ პასუხს. თანხმობა მიებმის ზუსტად იმ ვერსიას, რომელიც მშობელმა ნახა. ერთი ან ორივე guardian-ის აუცილებლობა სკოლის წესით განისაზღვროს; არ გამოიცნოთ. ფინანსური გადახდა თავისთავად თანხმობა არ არის. ვადა და გაუქმების შესაძლებლობა მკაფიო იყოს.

ეს სამუშაო თანხმობის აღრიცხვის პროცესია; ჩვეულებრივი ღილაკი ავტომატურად კვალიფიციურ ელექტრონულ ხელმოწერად არ აღწეროთ.

## 7. კლუბები და მოლოდინის სია

`clubs`, `club_sessions`, `club_enrolments`, `waitlist_entries`: კლასები/ასაკობრივი დაშვება, პასუხისმგებელი, capacity, გრაფიკი, ფასი თუ არსებობს, consent requirement და ჩარიცხვის პერიოდი.

MVP განაწილება: გამოქვეყნებული first-come წესი და timestamp-ით დალაგებული სია. capacity დაიცავით transaction/locking-ით. cancellation-ის შემდეგ შემდეგ ოჯახს დროით შეზღუდული შეთავაზება გაუგზავნეთ; სხვა ბავშვის ადგილი ჩუმად არ დაიკავოთ. კურსების დროის კონფლიქტი გამოაჩინეთ. ფასიანი ადგილის დროებითი დაჭერის ვადა და გადახდის ჩავარდნისას გათავისუფლება ერთ პროცესში იყოს.

მოსწავლის სურვილი და guardian-ის საბოლოო ავტორიზაცია განცალკევდეს იქ, სადაც სკოლის წესით საჭიროა. სტატუსები: requested/waitlisted/offered/enrolled/cancelled. ჯგუფური იმპორტიც იმავე წესებს გადიოდეს.

## 8. შემდეგი ეტაპის პორტფოლიო და შეჯამება

პორტფოლიო: მოსწავლის ნამუშევარი, რეფლექსია, საგანი, სასწავლო მიზანი, პედაგოგის უკუკავშირი, გამოქვეყნების სტატუსი. default private; სხვა ოჯახები ვერ ხედავენ. საჯარო გამოფენა მოითხოვს ცალკე განხილვასა და საჭირო თანხმობას. ფაილების შენახვას DMS-ის უსაფრთხო ინფრასტრუქტურა შეიძლება გაუზიაროს, მაგრამ სასწავლო და ადმინისტრაციული უფლებები არ აურიოთ.

კვირის შეჯამება: მომავალი ვადები, გამოქვეყნებული ახალი რესურსები და ოჯახის მოსაგვარებელი მოქმედებები; სკოლის/ოჯახის სიხშირის პარამეტრები, მხოლოდ უფლებამოსილი ბავშვის ინფორმაცია. საწყის ვერსიაში deterministic templates საკმარისია. AI-სთვის ბავშვების მონაცემების გარე გაგზავნა ამ დანართით არ არის ავტორიზებული.

## 9. რა დაემატა პროტოტიპს

`design/app/SchoolServices.tsx` და `services.css`; პორტალში ახალი „სერვისები“ პუნქტი. მუშაობს დროის არჩევა/გაუქმება, კლუბის არჩევა/მოლოდინის სია, მშობლის თანხმობა/უარი, გაცდენის მოთხოვნის დროებითი სტატუსი და staff-ის ფიქციური განხილვა.

ყველა მოქმედება დროებით React state-შია. სერვერის, რეალური შეტყობინების ან მუდმივი შენახვის გარეშე. როლის/ბავშვის/გვერდის შეცვლისას state შეიძლება თავიდან შეიქმნას. staff-ის გაცდენის მაგალითი დამოუკიდებელია მშობლის მაგალითისგან — cross-role მონაცემთა კავშირი განხორციელებული არ არის. დირექტორი staff როლად განისაზღვრა. დემო მონაცემები აშკარად მონიშნულია.

დოკუმენტების მოდული ცალკე აღწერილია `07-document-management-spec.md`-ში. Laravel-ს ახლა სხვა სამუშაოც ემატება; ამ პროტოტიპის არსებობა არ ნიშნავს, რომ root backend-ში ეს ფუნქციები უკვე შესრულებულია.

## 10. მიღების შემოწმებები და გაზომვა

- პარალელურად ერთი თავისუფალი slot/კლუბის ადგილი მხოლოდ ერთ მომხმარებელს მიენიჭება.
- სხვა ოჯახი/სკოლა ვერ კითხულობს booking/consent/absence ჩანაწერს, პირდაპირი ID-ითაც.
- თანხმობის ახალი ვერსია ძველ პასუხს ახალ თანხმობად არ ასაღებს.
- მოთხოვნის მიღება attendance-ის ფაქტს ჩუმად არ ცვლის.
- notification failure არ იწვევს ორმაგ booking-ს და მოთხოვნის დაკარგვას.
- გაუქმება, ვადის ამოწურვა, timezone და განმეორებითი submit ტესტირებულია.

გაზომვა: უპასუხო მოქმედებების წილი, შეხვედრის თვითმომსახურებით დაჯავშნის წილი, გაცდენის განხილვის მედიანური დრო, კლუბის ადგილის შევსება და waiting-list conversion. მიზნობრივი რიცხვები დასაწყისში არ გამოიგონოთ: ჯერ შეაგროვეთ 2–4 კვირის საწყისი მაჩვენებლები, შემდეგ სკოლასთან შეთანხმდეს გაუმჯობესების მიზანი.
