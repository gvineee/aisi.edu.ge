# 0006 — პერსონალის ცნობარი, დატვირთვა და ნამუშევარი საათები

**თარიღი:** 2026-10-27 · **სტატუსი:** მიღებული

## კონტექსტი

EduPage-ის სრულ ცხრილში (aSc, 2026/2027) 35 მასწავლებელია, 21 კლასი, 240 დატვირთვა და 604 გაკვეთილი კვირაში. ფაილში ელფოსტა არ წერია. ჩვენთან `lessons.teacher_id` და `teacher_assignments.user_id` სავალდებულოდ ანგარიშზე (users) მიუთითებდა. ანგარიშის შექმნა კი მხოლოდ მოწვევით შეიძლება, სახელით დამთხვევა და პაროლის გადმოტანა დაუშვებელია. ამიტომ ცხრილს ვერ შემოვიტანდით, სანამ ყველა მასწავლებელი ანგარიშს არ გაიხსნიდა.

სკოლას ასევე სჭირდება ნამუშევარი საათების დათვლა ბუღალტერიისთვის, მათ შორის იმ მასწავლებლებისთვის, ვინც პორტალში არ შედის.

## გადაწყვეტილება

1. **`staff_members`**: სკოლის თანამშრომელი ანგარიშისგან დამოუკიდებლად. მისი ველებია სახელი, შემოკლება, ვაკანსია („ახალი“), სტატუსი და არასავალდებულო `user_id`. ეს MIS-ების საერთაშორისო პრაქტიკაა: თანამშრომლის ჩანაწერი ≠ შესვლის ანგარიში.
2. **`staff_member_id`** დაემატა გაკვეთილს, დატვირთვას (`teacher_assignments`) და კლასის დამრიგებელს (`homeroom_staff_member_id`). `teacher_id`/`user_id` nullable გახდა, ხოლო ანგარიშიანი ჩანაწერები ძველებურად მუშაობს.
3. **ანგარიშის მიბმა** (`LinkStaffAccount`) ადმინისტრატორის ხელით ხდება, სკოლის აქტიურ წევრზე. მიბმისას ანგარიში ჩაიწერება პიროვნების გაკვეთილებზე, დატვირთვასა და დამრიგებლობაზე, რის შემდეგ მასწავლებლის პორტალი, დასწრება და ჩანაცვლება ამ ჩანაწერებს ხედავს. მიბმა და მოხსნა აუდიტში იწერება.
4. **ერთობლივი გაკვეთილი** (ერთი მასწავლებელი, რამდენიმე კლასი) ინახება თითო კლასზე ცალკე სტრიქონად, საერთო `joint_key`-ით. კონფლიქტის შემოწმება და საათების დათვლა მას ერთხელ ითვლის.
5. **`asc-timetable` იმპორტი**: ზარები → საგნები (მხოლოდ გამოყენებული) → ოთახები → პერსონალი → კლასები → ჯგუფები (მხოლოდ გამოყენებული, „მთელი კლასის“ გარეშე) → დატვირთვა → გაკვეთილები.
   - ცხრილი შეიქმნება **draft ვერსიად**, აქტივაცია ცალკე ხდება.
   - დაცვის წესები: dry-run, `import_identity_maps`, ხელით შეცვლილის შენარჩუნება და დუბლიკატის ანგარიში.
   - `--adopt-same-named` ხელით შექმნილ იგივე სახელის საგნებსა და ოთახებს გამოიყენებს, ადამიანებს არასდროს.
6. **ნამუშევარი საათები** (`CalculateWorkedHours`): დღის მიხედვით ითვლება მოქმედი ვერსიიდან, `ResolveDailyLessons`-ის წესით, დღესასწაულების (`non_teaching_periods`) გარეშე.
   - ჩატარებული = დაგეგმილი − გაუქმებული − სხვამ ჩაატარა + ჩაანაცვლა.
   - თანხა არ ითვლება, რადგან ტარიფი სკოლის გადასაწყვეტია. CSV ექსპორტი აუდიტში ჩაიწერება.

## შედეგები

- ცხრილი, დატვირთვა და საათები EduPage-ის იმპორტისთანავე სრულია.
- მოსწავლე და მშობელი თავის განრიგს `/portal/my-timetable`-ზე ხედავს ვერსიის აქტივაციისთანავე. მასწავლებელი თავისას ხედავს ანგარიშის მიბმის შემდეგ.
- ღია საკითხები:
  - საათის ტარიფი და ანაზღაურების წესი (ბუღალტერია);
  - მეორე დამრიგებელი, თუ ანგარიში არ აქვს;
  - მოსწავლეების ჯგუფებში განაწილება (EduPage-ის მოსწავლეების ექსპორტით, ცალკე და დაცულად).
