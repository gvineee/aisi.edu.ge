# 0002 — დიზაინის წყარო ფაზა 1-ისთვის

## განახლება (იმავე დღეს)

პირველი ვერსია ამ დოკუმენტისა დაწერილი იყო მაშინ, როცა `design/`-ში მხოლოდ `design/app/page.tsx` არსებობდა (ინგლისურენოვანი loading-skeleton placeholder) და `CLAUDE.md`-ს არ ჰქონდა დანართი დიზაინის შესახებ. მას შემდეგ:

- `CLAUDE.md`-ს დაემატა სექცია „აუდიტისა და საბოლოო დიზაინის დანართი", რომელიც პირდაპირ მიუთითებს: „პროტოტიპი მდებარეობს `design/app/AisiConcept.tsx` და `design/app/globals.css`".
- `design/app/AisiConcept.tsx` ფაილად გაჩნდა — **სრული, აისი-ბრენდირებული, ქართულენოვანი ინტერაქციული კონცეფცია**, რომელიც მოიცავს როგორც საჯარო საიტს (header, hero, „სწავლა და განვითარება" 3 პროგრამა-ბარათით, „პორტალის პრომო", „სასკოლო ცხოვრება", კონტაქტი, footer), ისე პორტალის დემოს (როლის გადამრთველი: მშობელი/მოსწავლე/მასწავლებელი/ადმინისტრაცია; sidebar ნავიგაცია; „დღეს" დაფა; განრიგი დღეების მიხედვით; ბიბლიოთეკის ძებნა; გადახდების ისტორია ცხრილით; მასწავლებლის დასწრების ჟურნალი; ადმინის ბრენდის ფერის გადამრთველი; mobile bottom-nav).
- `design/app/page.tsx` ახლა რეალურად რენდერავს `AisiConcept`-ს (`import AisiConcept from './AisiConcept'`), ანუ აღარ არის უბრალო skeleton.
- `design/app/globals.css` განახლდა და შეიცავს რეალურ token-ებს, რომლებიც ზუსტად ემთხვევა `docs/03-brand-and-marketing.md`-ის ბრენდს: `--foreground/--primary: #132b45` (Midnight), `--orange: #f5683c` (Dawn), Noto Sans Georgian `@font-face` (`/noto-georgian-regular.ttf`, `/noto-georgian-bold.ttf`), responsive breakpoints (1600/1200/1000/950/700/370px), 44px+ ღილაკები, `prefers-reduced-motion` მხარდაჭერა, `.skip`-link, `focus-visible` outline.
- `design/public/`-ს დაემატა რეალური ასეთები: `logo-concept.png`, `school-life.jpg`, `noto-georgian-regular.ttf`, `noto-georgian-bold.ttf`, `FONT-LICENSE.txt`.
- `CLAUDE.md` ასევე მიუთითებს `docs/04-design-handoff.md`-ზე, როგორც „დიზაინის პრაქტიკულ რუკაზე" — **ეს ფაილი ჯერ არ არსებობს დისკზე** (`docs/`-ში მხოლოდ 01/02/03 + `decisions/` + `implementation-status.md` წყაროა). ეს არ არის გამოგონილი; უბრალოდ ჯერ არ მოსულა. აღვნიშნავთ როგორც მოლოდინში მყოფ დამოკიდებულებას და გავაგრძელებთ დამოუკიდებელ სამუშაოს `AisiConcept.tsx` + `docs/03`-ის საფუძველზე, სანამ ეს ფაილი გამოჩნდება.

**წინა დასკვნა („`design/`-ს არა აქვს აისის ვიზუალური ენა") იყო სწორი იმ მომენტისთვის, მაგრამ მოძველებულია.** ეს არ არის დიზაინის შეცვლა ჩემი მხრიდან — უბრალოდ ფაილი დაემატა handoff-ს მას შემდეგ, რაც პირველი ინვენტარი დავწერე. ქვემოთ განახლებული გადაწყვეტილებაა.

## გადაწყვეტილება (განახლებული)

1. **`design/app/AisiConcept.tsx` + `design/app/globals.css` არის ვიზუალური/ინტერაქციის წყარო ფაზა 1-ისთვის**, `docs/03-brand-and-marketing.md`-თან ერთად ფაქტების/ტონის წყაროდ. კონცეფციის კომპოზიცია (hero სტრუქტურა, „სწავლა" ბარათები, portal sidebar/dashboard/bottom-nav ლეიაუთი, spacing/radius/token-ები) გადავაქციოთ რეალურ Inertia + React გვერდებად Laravel-ის starter kit-ის Vite გარემოში.
2. **რაც კონცეფციაშია დემო/inline მონაცემი (როლების მასივი, გაკვეთილების სია, გადახდის თანხები, დასწრების პროცენტები) არ გადადის კოდში hardcoded სახით.** ეს ველები რეალურ აპში მოვა DB-დან (Academics/Finance/Timetable domain-ებიდან) policy-ით შემოწმებული endpoint-ებით — `CLAUDE.md`-ის უცვლელი მოთხოვნა #10 („ცარიელი dashboard არ შეავსო შემთხვევითი ყალბი ფინანსებით/შეფასებებით") ამ კონცეფციის დემო რიცხვებზეც ვრცელდება.
3. **როლის გადამრთველი (`role` state კონცეფციაში) პრეზენტაციის ხელსაწყოა** — production-ში აქტიური როლი და ხილული მონაცემი განისაზღვრება server-side membership/policy-დან, არა client-side toggle-ით. კონცეფციის footnote ამასვე ადასტურებს: „ვიზუალური პროტოტიპი · ფორმები მონაცემებს არ აგზავნის".
4. **ვიზიტის ჯავშნის დემო ფორმა** (`ვიზიტის დაგეგმვა` დიალოგი) რეალურ გვერდზე უნდა შეინახოს server-ზე ტევადობის კონტროლით — არა მხოლოდ `setSent(true)` ლოკალური სტეიტით, როგორც კონცეფციშია მონიშნული.
5. **shadcn/ui კომპონენტების ტულინგი** (`design/components/ui/*`) რჩება საწყის წერტილად, ხელახლა აწყობილი Laravel-ის Vite + React გარემოში (არა vinext/Next.js runtime).
6. **`docs/04-design-handoff.md` უკვე გამოჩნდა** (იმავე სესიის განმავლობაში) და შეიცავს ზუსტ component-mapping ცხრილს (პროტოტიპის ნაწილი → Laravel/React სამიზნე: `TenantBrand`/`TenantThemeProvider`, `PublicLayout`, `pages/public/Home`, `VisitRequestDialog`, `PortalLayout`, `pages/parent/Dashboard`, `TimetableDay`, `LibraryIndex`, `InvoicesIndex`, `AttendanceRegister`, `SchoolBrandSettings`). ეს დოკუმენტი ზემოთ მოცემულ გადაწყვეტილებებს არ ეწინააღმდეგება — პირიქით, ადასტურებს იმავე მიდგომას უფრო დეტალურად. ფაზა 1-ის კომპონენტების აწყობისას ვიყენებთ ამ მაპინგს პირდაპირ.

## შედეგები

- Phase 1-ის საჯარო გვერდები (მთავარი, შესახებ, სწავლა, სასკოლო ცხოვრება, კონტაქტი) აშენდება `AisiConcept.tsx`-ის სექციური სტრუქტურის მიხედვით, რეალურ CMS-შენახულ კონტენტზე დაყრდნობით.
- პორტალის დაფის ვიზუალური ენა (sidebar, stat-card grid, day-card, bottom-nav) გამოყენებული იქნება ფაზა 2-ში იმავე პრინციპით — რეალურ მონაცემებზე, არა დემო მასივებზე.
- ბრენდის ფერის switch (`theme-options`, Midnight/Dawn ↔ Teal ალტერნატივა) მიუთითებს, რომ tenant-ს შეიძლება ჰქონდეს ალტერნატიული აქცენტი; ეს თავსდება `brand_settings`-ის token-ური მოდელის ფარგლებში (იხ. `docs/02`, თავი 7.1), არა hardcoded კომპონენტში.
