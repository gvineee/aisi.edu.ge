# 0005 — კურსები, ჯგუფები და პირადი განრიგი

თარიღი: 2026-10-26 · სტატუსი: მიღებულია

## კონტექსტი

EduPage-ის „კურსი“ არის საგანი × კლასი × მასწავლებელი × (მთელი კლასი ან ჯგუფი). ჩვენთან იგივე როლს ასრულებს `TeacherAssignment` (user + class + subject ტექსტი). ამაზეა დამოკიდებული Assignments, Gradebook, ტაბელი და მასწავლებლის სივრცე. `CLAUDE-EDUPAGE-MIGRATION.md` §3 ითხოვს გადაწყვეტილებას: გაფართოება თუ ახალი `Course` მოდელი.

## გადაწყვეტილება

1. **`TeacherAssignment` ფართოვდება და მეორე მოდელი არ იქმნება.** დაემატა `subject_id`: ტექსტი რჩება, backfill მხოლოდ ზუსტი დამთხვევით. დაემატა `student_group_id`: null ნიშნავს მთელ კლასს. თანასწავლება = ორი assignment იმავე class/subject/group-ზე. ცალკე `Course` შემოვა მხოლოდ მაშინ, თუ ექსპორტი (E3/E4) დაადასტურებს, რომ კურსს assignment-ისგან განსხვავებული სასიცოცხლო ციკლი აქვს (მაგ. რამდენიმე კლასის ერთი კურსი).
2. **ჯგუფი = `student_groups` + წევრობა.** წევრობა ცხადია, ავტომატურად არავინ ემატება. გაკვეთილს აქვს `student_group_id`. ერთი კლასის სხვადასხვა ჯგუფი ერთ დროს შეიძლება ისწავლიდეს (`CheckLessonConflicts`). roster ჯგუფური გაკვეთილისთვის = ჯგუფის წევრები (`Lesson::rosterQuery`).
3. **ცხრილის ვერსია.** თარიღისთვის მოქმედებს წლის ის non-draft ვერსია, რომლის validity თარიღს მოიცავს და ყველაზე გვიან დაიწყო. თუ ვერსია არსებობს, მხოლოდ მისი გაკვეთილები ითვლება, თუ არა — მხოლოდ ვერსიის გარეშე. ასე ორი ვერსია ერთდროულად ვერასდროს გამოჩნდება. ვერსიის შეცვლა ძველ დასწრებას და ნიშნებს არ ეხება: ისინი კონკრეტულ `lesson_id`-სა და თარიღს ეკუთვნის.
4. **პირადი განრიგი** (`/portal/my-timetable`). ყოველი დღე `ResolveDailyLessons`-იდან მოდის. ეს წყარო dashboard-ებს უკვე ემსახურება, ამიტომ დღე და კვირა ერთმანეთს ემთხვევა.
   - მოსწავლე: საკუთარი კლასის მთელი კლასის გაკვეთილები და საკუთარი ჯგუფების გაკვეთილები.
   - მშობელი: აქტიური link + `can_view_academic`. `child` პარამეტრი მხოლოდ საკუთარ ბავშვებს შორის ირჩევს.
   - მასწავლებელი: საკუთარი გაკვეთილები, შემცვლელზე გადაცემულები მონიშნული. ამას ემატება იმ დღის ჩანაცვლებები: აქტიური `SubstitutionAssignment` ან `LessonException(substitution)`. ჩანაცვლება კლასზე მუდმივ წვდომას არ ქმნის: გაკვეთილის გვერდი შემცვლელს მხოლოდ იმ დღეს ეხსნება.
   - პასუხი `Cache-Control: private, no-store`-ით მიდის. service worker პროექტში არ არის.
   - ადმინისტრაციის რედაქტორი (`/portal/timetable`) ცალკე რჩება.

## შედეგი

backward-compatible: ძველი გაკვეთილები (ვერსიისა და ჯგუფის გარეშე) ადრინდელივით მუშაობს. dashboard-ებზე მოსწავლე და მშობელი ახლა მხოლოდ საკუთარი ჯგუფის გაკვეთილებს ხედავს. მასწავლებლის dashboard-ზე ჩანაცვლებები ისევ ცალკე სიაშია.
